## Implemented behavior

`WTK_PRODUCT_FACTORY_PROVISIONED=ON` applies only to PRODUCT. The default is OFF.
The new `stm32-factory-debug` / `stm32-factory-release` presets select it explicitly.
The factory STM32 source set excludes `app_calibration_wizard.c`,
`app_calibration_session.c` and `measurement_calibration_solver.c`. Compile guards
remove wizard entry/teardown, fitting UI and LOAD-preset tables/selection/formatting.
The calibration menu reports status/sequence and service instructions; it cannot
start a wizard. Blank media stays explicitly UNCALIBRATED after any OK gesture.
Bounded EN/PT-BR service messages use the existing internal fallback font.

The actual `app_product_init` / `app_product_step`, measurement session, DSP and
complex OSL correction remain. Boot still requires full usable OSL **and** a valid
Resource Pack. The unchanged calibration service/runtime loads through
`measurement_cal_store_load_full_usable`: schema 2/model 4, hardware compatibility,
CRC, commit marker, numerical validity and all 33 unique allowed keys are required.
An unusable newer slot cannot displace the older usable slot. No record, flag,
sequence, partition, measurement equation or ADC/DMA timing changed.

PRODUCT does not install calibration. Factory mode omits the calibration writer's
superloop step because it has no calibration mutation entry point; Resource Pack
and settings transactions retain their existing independent cooperative scheduling.
USART1 calibration installation remains in BRINGUP_CAL. Factory Debug explicitly
enables Resource Pack upload recovery as well as Release; legacy Debug's existing
opt-in recovery option is unchanged. Safety, fresh permits, range transitions,
K1 teardown, acquisition ownership, quiet mode, watchdog and fault handling remain
under their existing owners. Neither boot nor service instructions start excitation.

Missing/corrupt resources enter the existing internal PC-link recovery screen even
with valid OSL. Valid resources with blank/incompatible/corrupt OSL stay blocked.
Faults preempt both; charger/residual denial cannot start normal acquisition.
Persisted OSL is calibration availability, not physical qualification. The existing
PRODUCT session still starts with UNQUALIFIED; synthetic PC records cannot assert
QUALIFIED. Curves OFF/ON remain independently selectable and replacement OSL still
invalidates overlay bindings through sequence/CRC checks.

## Reproduction and deployment

From the repository root:

```powershell
# Archive/build the exact baseline without changing the active checkout.
python Firmware/tools/product_factory_matrix.py --baseline 334798c54e372b1267b01156bd742e20a4ea1460 --out Firmware/build/factory-baseline
# Twelve ARM images, A01 maps/NM/sections/stack evidence and compact sizes.csv.
python Firmware/tools/product_factory_matrix.py --out Firmware/build/factory-arm
# Eight host mode/type/curve combinations; full Python suite uses each C fixture.
python Firmware/tools/product_factory_matrix.py --host --out Firmware/build/factory-host
```

For a single firmware build, from `Firmware/`:

```powershell
cmake --preset stm32-factory-release -DWTK_ENABLE_SUPPLEMENTARY_CURVES=OFF
cmake --build --preset stm32-factory-release
# Legacy remains the default:
cmake --preset stm32-release -DWTK_PRODUCT_FACTORY_PROVISIONED=OFF
cmake --build --preset stm32-release
```

After resolving the [A05 assembly/bench gates](../a05/bringup-checklist.md), use SWD
to deploy BRINGUP_CAL, connect a 3.3 V USB-UART at J_UART (1 GND, 2 MCU TX to adapter
RX, 3 MCU RX to adapter TX; no adapter power lead), and use the existing
[capture](../../../Firmware/tools/PC_CAL_CAPTURE.md) and
[installation](../../../Firmware/tools/PC_OSL_INSTALL.md) commands. For example:

```powershell
python tools/pc_cal_capture.py identify --port COM5
python tools/pc_osl_install.py install --port COM5 --candidate candidate.bin --report installation.json --readback installed.bin
```

Verify installation/readback/reset in BRINGUP_CAL, then flash the experimental
PRODUCT via **SWD**, preserving external W25Q. Supply its required Resource Pack
using the existing PC-link recovery mechanism. Restart and check calibration status,
then request a passive-component measurement with OK. There is no native USB
firmware switch, PRODUCT OSL installer or new on-device OPEN/SHORT trim.

Run the complete synthetic workflow against a factory host build (Windows example):

```powershell
python Firmware/tools/pc_osl_install.py simulate --bridge Firmware/build/factory-host/host-debug-factory-ON-curves-ON/tests/Debug/wtk_pc_cal_capture_bridge.exe --output Firmware/build/factory-demo
```

Use a new demo directory. Generated campaigns, binaries and verbose evidence remain
ignored; the scripts and [compact size comparison](A06.2c-sizes.csv) are committed.
The archived baseline tool requires matching pinned submodule SHAs and fixes only
its archived Git-banner detector so a later checkout cannot mislabel baseline code.
