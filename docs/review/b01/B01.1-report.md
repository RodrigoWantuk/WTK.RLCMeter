## Delivered operator utility

[pc_firmware_deploy.py](../../../Firmware/tools/pc_firmware_deploy.py) supports
doctor/build/inspect/probe/program/verify/report, true non-target dry runs,
sealed image manifests, explicit B01/board/operator/supply/stage authorization,
UID/image-specific approval and separate boot/application evidence. Actual
[Windows quickstart](../../../Firmware/tools/PC_FIRMWARE_DEPLOY.md) covers wiring,
dependencies, all three transitions, failures and recovery. No installation command,
GPIO override, USB bootloader, mass erase, option/protection modification or W25Q access.

Build selects stm32-bringup, stm32-bringup-cal or stm32-factory-release, explicitly
curves OFF; factory ON only for requested factory PRODUCT. Legacy/default build
behavior remains unchanged and independently tested. Manifest inspection reconstructs
BIN from real ARM ELF PT_LOAD data, checks vectors/memory/linker/configuration,
profile/factory/curves/version/boot contracts, linked Flash/accounted RAM/stack,
timestamps, source dirty/fingerprint, compiler/preset and file hashes. Dirty images
cannot authorize physical programming; source edits during build invalidate production.
Older explicitly pinned clean images are allowed; filenames alone are never identity.

Program requires named physical B01 prerequisites, no unresolved STOP/UNKNOWN,
current SAFE/no-acquisition/no-storage-transaction acknowledgement, debug reset/halt/
watchdog acceptance, no application bootloader and explicit internal-Flash approval.
Real probe/verify also require a physical SAFE debug-stage acknowledgement: they
can reset/halt and are not electrically passive. Firmware boot/application remain
NOT_TESTED after successful internal verification. Reports never qualify calibration.

Inputs are copied into a verified private staged BIN before target access. Paths are
subprocess arrays/environment DATA, not shell/Tcl text. Output directories are
reserved exclusively. Fresh preflight precedes writes and is repeated inside the
program invocation. Missing markers, exit-zero incomplete results, interruptions,
unexpected reset, timeout or byte mismatch fail/leave UNKNOWN without automatic retry.
All 64KiB are read back; image prefix bytes/hash and unaffected internal pages are checked.
B01 references remain unchanged. Actual programmer logs can be imported as hashed
sidecars; unfamiliar native logs remain UNKNOWN rather than guessed.

The Windows executable SHA and interface/target scripts are checked by the toolkit;

Primary evidence used:

- [Pinned xPack release](https://github.com/xpack-dev-tools/openocd-xpack/releases/tag/v0.12.0-6)
  and its downloaded scripts/binary, not an assumed generic OpenOCD installation.
- [Exact flash driver source](https://github.com/openocd-org/openocd/blob/eb6f2745b/src/flash/nor/stm32f1x.c):
  erasing first=0,last=num_sectors−1 calls mass erase. Therefore the toolkit requests
  each occupied 1KiB page individually, even all 64 pages for BRINGUP, then write_bank
  without erase. Last-page slack is erased; this is not called "no erase".
- [Flash Tcl API source](https://github.com/openocd-org/openocd/blob/eb6f2745b/src/flash/nor/tcl.c)
  establishes flash-list dictionary fields; [ST-Link source](https://github.com/openocd-org/openocd/blob/eb6f2745b/src/jtag/drivers/stlink_usb.c)
  establishes optional reported-voltage formatting. Absent voltage stays UNKNOWN.
- [OpenOCD memory/reset commands](https://openocd.org/doc/html/General-Commands.html)
  and [Flash API](https://openocd.org/doc/html/Flash-Commands.html) establish documented
  read_memory/dump_image/reset-init and bank operations. Toolkit-owned markers avoid
  inventing a native log parser. The production Tcl is executed under actual OpenOCD
  with explicitly synthetic API mocks, **without adapter/target init**.

Expect device-family ID 0x410, ARM Cortex-M3, Flash size word 64KiB, one stm32f1x
bank at 0x08000000, no RDP/option/write protection and exact expected UID. These
family identifiers cannot prove a genuine F103C8T6 or Bluepill pinout; R05 part/module
inspection remains mandatory. Unknown IDs/geometry, 128KiB, protected/unpowered or
ambiguous targets STOP. No geometry override, mass erase or protection unlock exists.
Upstream target configuration freezes watchdogs while halted and uses SRAM for
programming. This debug behavior is acknowledged, never a safety qualification.
No resume/reset-run is emitted; the last reported target state is halted. Actual
post-disconnection behavior and safe outputs still require bench observation.
