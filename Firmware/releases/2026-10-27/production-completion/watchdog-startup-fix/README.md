# Deployed production: watchdog startup correction

October 27, 2026 — **DEPLOYED / READY / SAFE / UART TELEMETRY VERIFIED**. Broader physical qualification remains pending. This supersedes the initial prepared 603f671 image in the parent directory.

The owner explicitly authorized programming after confirming the instrument was still powered. The initial image programmed and read back correctly, but its newly checked startup path exposed an existing IWDG initialization error: PR/RLR update flags were awaited before IWDG was enabled. Actual UART reported fault 0x100; K1 stayed SAFE, range disabled and no acquisition started. Live register reads showed LSI ready, PR=0, RLR=4095 and both update flags pending.

The fix follows the pinned [ST HAL initialization sequence](https://github.com/STMicroelectronics/stm32f1xx-hal-driver/blob/master/Src/stm32f1xx_hal_iwdg.c): enable, unlock/configure, bounded synchronization wait, reload, then mark started. The startup error latch remains intact. Tests execute the actual BSP against a deterministic register-update model for success, absent LSI and stuck update flags. This tests software ordering and failure handling, not physical reset timing.

The corrected image source is `6bb3a680b9ba` (full SHA in the manifest/report). [firmware.zip](firmware.zip) contains the sealed image, ELF, generated config, linker and manifest. It uses 75,092 Flash bytes / 15,204 accounted RAM bytes, including a 2,048-byte stack reserve. The explicit UID-bound 128-KiB profile remains required; generic C8 geometry is unchanged. BIN SHA-256: `b101b86452cc834fa88a30431c8406188fd7d9ff67b053451ec8ef2732d08824`.
